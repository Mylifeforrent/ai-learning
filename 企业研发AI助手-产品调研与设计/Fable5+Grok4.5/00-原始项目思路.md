# 企业研发 AI 助手（当前项目思路整理）

> 根据当前对话整理，供后续 PRD/架构设计使用。

## 一、产品定位

目标不是 AI Coding Agent，而是 **Enterprise AI Developer Assistant（企业研发助手）**。

特点：

- 固定业务页面 + AI 对话框，而不是纯 Chat。
- AI 作为 Workflow Orchestrator（工作流编排者）。
- 打通 Jira、Confluence、GitHub、Jenkins 等研发工具。

---

## 二、设计灵感 / 参考产品

### 产品

- Cursor（Agent 模式）
- Claude Code
- GitHub Copilot Agent
- Hermes Agent（尤其 Skills 与 Terminal Backend 思路）

### 框架思想

- Tool Calling
- Workflow Orchestration
- Skills Marketplace
- Memory
- Docker Sandbox（按需）
- Jenkins 作为正式自动化测试执行平台

---

## 三、V1 功能目标

### 1. 日常开发助手

- Chat + Skills
- 用户可编写/分享 Skills
- Memory（个人、项目、知识）
- 导出 Markdown / JSON

### 2. 自动化测试中心

流程：

上传测试包（Playwright/Python 等）
→ Jenkins Job
→ 查询结果
→ AI 汇总、美化
→ 用户审核
→ 更新 Jira / Confluence
→ Release 证据沉淀

原则：

- 测试运行在 Jenkins
- AI 不直接运行正式测试
- 邮件仅生成草稿，不发送

### 3. Release Assistant

读取：

- Jira
- GitHub PR
- Release Template

自动：

- 生成 Change Request
- 调企业内部合规检查
- 生成 Release Checklist
- 生成邮件草稿

---

## 四、长期目标

打造 AI Native Developer Portal。

新增：

- Workflow Builder
- 更多 Connector
- 多模型支持
- 多租户
- 可插拔 Sandbox Backend
- 企业知识库
- 自动化研发流程

## 五、推荐技术架构

### 前端

- Next.js
- React
- TailwindCSS

### 后端

- FastAPI

### Agent Runtime

**自行实现轻量 Runtime**

包含：

- Planner
- Tool Router
- Memory
- Model Adapter
- Workflow Engine

不绑定 Claude Agent SDK。

### 模型

建议通过统一 Adapter（如 LiteLLM 思路）支持：

- Claude
- GPT
- Gemini
- Qwen
- DeepSeek

### Skills

参考 Hermes：

```
skills/
  jira/
  release/
  mail/
  test/
```

Skill 建议包含：

- prompt
- yaml
- python/shell
- permissions
- timeout
- sandbox

### Sandbox

采用 Docker。

作为 Tool，而不是核心。

仅用于：

- Python
- Shell
- Excel
- XML
- 日志分析
- 数据统计

### 自动化测试

正式测试：

Jenkins。

AI：

- Trigger
- Polling
- Summary
- Jira
- Confluence

### Memory

三层：

- User Memory
- Project Memory
- Knowledge

保存：

- Markdown
- Metadata(Postgres)

支持导出迁移。

## 六、权限设计

认证：

- SSO 为主
- SSO 失效可账号密码

AI：

允许：

- 更新 Jira
- 更新 Confluence

不允许：

- 自动发送邮件

邮件：

仅生成 Draft。

---

## 七、多租户

目前主要服务单企业。

数据库建议预留：

tenant_id

方便未来扩展。

---

## 八、Skills 管理

允许普通用户开发。

建议：

个人 Skill 可直接使用。

团队共享 Skill：

管理员审核后发布。

---

## 九、需要确认

1. Workflow Builder 是否进入 V1？
2. Memory 自动保存策略。
3. Connector SDK 规范。
4. Docker 生命周期（持久或临时）。
5. Release Template 配置方式。
6. Jenkins Job 标准接口。

---

## 十、核心原则

- AI 是编排者，不替代 Jenkins。
- Docker 是工具，不是平台。
- Workflow 比 Chat 更重要。
- Connector、Workflow、Memory、Skills 是核心资产。
- LLM 可替换，不绑定单一厂商。
