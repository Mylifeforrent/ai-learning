## 1. 摘要与分析框架

### 1.1 一句话结论

本产品不与 Cursor / Claude Code / Copilot 抢「写代码」；真正对手是 **GitLab Duo Agent Platform、Atlassian Rovo（+Rovo Studio）、以及企业内部已购订阅里的「免费附赠 AI」**。空档清晰：**跨异构工具链编排（Jira + Confluence + GitHub + Jenkins）+ Jenkins 正式测试执行 + 人审治理**——巨头各自只做自家生态内编排，Jenkins 存量几乎不在其 AI 叙事里。

### 1.2 本产品必须坚持的定位边界

| 我们是 | 我们不是 |
|---|---|
| Enterprise AI Developer Assistant | AI Coding Agent |
| 固定业务页面 + AI 对话框 | 纯 Chat / 纯 IDE Agent |
| Workflow Orchestrator | 替代 Jenkins / 替代 CI 平台 |
| 打通异构研发工具链 | 单厂商生态深度绑定 |
| Docker = 按需 Tool | Docker = 测试/执行平台 |
| LLM 可替换 Adapter | 绑定 Claude / GPT / 单一 SDK |

（原则来源：[00-原始项目思路.md](./00-原始项目思路.md)）

### 1.3 对比维度（全文统一）

后续所有深度对比均按以下 9 维打分/描述：

| 维度 | 含义 | 对本产品的权重 |
|---|---|---|
| **定位** | Coding / SDLC 编排 / 测试专精 / 门户 | 高 |
| **目标用户** | 个人开发者 vs QA/Release/平台团队 | 高 |
| **核心能力** | Chat、Agent、Workflow、结构化业务页 | 高 |
| **工具集成** | Jira / Confluence / GitHub / Jenkins / 其他 | **极高** |
| **权限治理** | SSO、动作分级、人审、审计、草稿策略 | **极高** |
| **Skills/扩展** | 用户可写 Skill、审核发布、Marketplace | 高 |
| **定价/部署** | SaaS / 私有化 / 席位 / 用量 / 自建 | 中高 |
| **与本产品重叠度** | 低 / 中 / 高（按 V1 三能力） | — |
| **差异化空间** | 本产品可打穿的空档 | — |

**重叠度评分口径（V1）**：日常开发助手 · 自动化测试中心（Jenkins 编排）· Release Assistant。三者均强=高重叠；仅 Chat/编码强=低重叠。

### 2.1 纯 Coding Agent

| 产品 | 代表能力 | 与本产品关系 |
|---|---|---|
| [Cursor](https://cursor.com) Agent | IDE 内多步改码、工具调用、代码库上下文 | 灵感来源；**非同赛道** |
| [Claude Code](https://docs.anthropic.com/en/docs/claude-code) | 终端 Agent、工具链、仓库级任务 | 灵感；可作为「引擎」被调用，非竞品 |
| [GitHub Copilot](https://github.com/features/copilot) Agent / Cloud Agent | IDE + github.com Agent、PR、Code Review | 编码强、跨工具业务流程弱 |
| [Windsurf](https://windsurf.com) / Cascade | IDE Agent、多文件编辑 | 同 Coding 红海 |
| OpenAI Codex / 类似 CLI Agent | 终端编码 Agent | 同上 |

**判断**：红海且模型厂商亲自下场（Gartner 2026 将 Anthropic / Cursor / GitHub / OpenAI 列为 coding agent 领导者）。本产品 **明确不进入** 此象限的正面竞争。

### 2.2 平台内嵌 AI（真正的近邻对手）

| 产品 | 生态中心 | 编排范围 |
|---|---|---|
| [GitLab Duo Agent Platform](https://about.gitlab.com/gitlab-duo-agent-platform/)（2026-01 GA） | GitLab | Issue → MR → Pipeline → Security 全链路；可 MCP 外接，但**产品叙事以迁出 Jenkins 到 GitLab CI 为主** |
| [Atlassian Rovo](https://www.atlassian.com/software/rovo) / [Rovo Studio](https://www.atlassian.com/software/rovo/studio) | Jira / Confluence / Teamwork Graph | 搜索、Chat、Agents、工作流内嵌；经 MCP 连第三方；**Jenkins 正式测试编排非核心** |
| Azure DevOps + GitHub Copilot 企业能力 | Microsoft 工具链 | Azure Boards / Repos / Pipelines 内 AI；跨 Atlassian+Jenkins 弱 |
| [JetBrains AI](https://www.jetbrains.com/ai/) | IDE | 编码与 IDE 内助手，非企业 SDLC 门户 |

### 2.3 DevOps / 测试 AI

| 产品 | 焦点 | 与本产品 V1「测试中心」关系 |
|---|---|---|
| [Katalon TrueTest](https://katalon.com/truetest)（2025 GA） | 从生产用户行为生成/自愈回归用例 | **生成与维护测试**；不做跨工具发布证据链 |
| Testim / mabl / Tricentis | 自愈 UI 测试、智能选择器 | 测试执行平台；非 Workflow Orchestrator |
| Launchable（已被 CloudBees 收购） | 测试选择优化、失败诊断 | 缩短 CI 反馈；不编排 Jira/Confluence/Release |
| [Diffblue Cover](https://www.diffblue.com/) | Java 单元测试自动生成 | 单元级；与 Jenkins 编排+人审汇总正交 |

### 3.2 Cursor

| 维度 | 内容 |
|---|---|
| **定位** | AI-native IDE + Agent，最大化个人编码吞吐 |
| **目标用户** | 个人开发者、创业团队、对 IDE 体验敏感的工程师 |
| **核心能力** | Agent 多步改码、代码库索引、Chat、Rules、MCP 工具 |
| **工具集成** | 以本地仓库与终端为中心；企业 Jira/Jenkins 非一等公民 |
| **权限治理** | 个人/团队级；缺企业级「动作分级 + 发布人审」产品化 |
| **Skills/扩展** | Rules、MCP、自定义指令；非「团队 Skill 审核后发布」 |
| **定价/部署** | 订阅制 SaaS；代码可本地，企业管控弱于门户产品 |
| **重叠度** | **低**（仅「对话式助手」体验可参考） |
| **差异化空间** | 不做 IDE；把 Cursor 级 Agent UX **下沉到固定业务页**（测试中心、Release），而不是仓库编辑 |

### 3.6 GitLab Duo Agent Platform ★ 近邻

| 维度 | 内容 |
|---|---|
| **定位** | GitLab 内嵌的 Agentic SDLC 平台（多 Agent + Flows + 治理） |
| **目标用户** | 使用 GitLab 的开发、安全、运维、管理者 |
| **核心能力** | Agentic Chat、Foundational Flows、CI 专家、MR/冲突处理、AI Catalog、外部 Agent（含 Claude Code/Codex）接入 |
| **工具集成** | **GitLab 一等公民**；经 MCP 可连 Jira/Slack/Confluence 等；对 Jenkins 的官方叙事是 **「Convert to GitLab CI/CD」迁出**，而非「长期编排 Jenkins 存量」 |
| **权限治理** | 工具级审批、审计事件、自托管/模型选择——企业治理标杆之一 |
| **Skills/扩展** | Flows、Catalog、外部 MCP；扩展性强但**仍以 GitLab 为控制面** |
| **定价/部署** | GitLab Duo / Credits；支持 .com、Self-Managed、Dedicated（[GA 公告](https://about.gitlab.com/blog/gitlab-duo-agent-platform-is-generally-available/)、[文档](https://docs.gitlab.com/user/duo_agent_platform/)） |
| **重叠度** | **形态重叠度高**（都是 SDLC 编排）；**工具链重叠度低**（本产品服务 GitHub+Jenkins+Jira 混搭） |
| **差异化空间** | 1）不要求企业迁 CI；2）Jenkins 是正式测试执行后端；3）固定业务页（测试中心/Release）而非「几乎每页都是 Chat」。**GitLab 客户不是主目标；「用了 GitLab 全家桶」的企业优先级下调。** |

关键反证：GitLab 文档明确提供 [Convert Jenkins → GitLab CI Flow](https://docs.gitlab.com/user/duo_agent_platform/flows/foundational_flows/convert_to_gitlab_ci/)——说明巨头策略是 **吞并 Jenkins**，而本产品策略是 **编排 Jenkins**。这是定位分水岭。

| LangGraph | Workflow 图、interrupt/人审、可观测性设计参考 | 非竞品；可选用或自研轻量引擎对照 |
| CrewAI / AutoGen | 多角色分工模式参考 | 非竞品 |
| **Hermes** | **Skills 目录结构、permissions/timeout/sandbox、多 Terminal Backend、模型可切换、agentskills.io**——与本产品 Skills/Docker-as-Tool 原则高度同构 | 非竞品；**直接借鉴实现范式**（[GitHub](https://github.com/nousresearch/hermes-agent)） |
| Claude Agent SDK | 成熟 Agent 循环 | **明确不绑定**；避免厂商锁死（见 [00](./00-原始项目思路.md)） |

**可执行洞察**：V1 Runtime = 自研轻量 Planner + Tool Router + Workflow + Memory + Model Adapter；Skills 包格式对齐 Hermes/agentskills 思路；Docker 仅作 Tool Backend，正式测试永不进 Docker 沙箱。

---

### 3.12 Backstage + AI / Port / Cortex（门户簇）

| 维度 | 内容 |
|---|---|
| **定位** | Internal Developer Portal：目录、所有权、Scorecard、脚手架、逐步 Agent 化 |
| **目标用户** | 平台工程、架构、研发效能 |
| **核心能力** | 服务元数据、权限与合规分数、自助创建；2025–2026 向 MCP / agent-operable 演进 |
| **工具集成** | 插件连接一切，但 **「开箱即用的测试中心 + Release Assistant」通常要自建** |
| **重叠度** | **短期中、长期高**（本产品长期目标即 AI Native Developer Portal） |
| **差异化空间** | V1 **不要先做通用目录**；用三个垂直 Workflow 证明价值，再长出 Portal。对已有 Backstage 的企业：定位为 **Portal 上的 Orchestration 层/插件**，而非替换 Backstage |

参考行业背景见 [01-市场调研.md](./01-市场调研.md) §2.3。

## 4. 竞争定位矩阵

### 4.1 矩阵 A：Coding 深度 × SDLC 编排广度

|  | SDLC 编排窄 | SDLC 编排宽 |
|---|---|---|
| **Coding 深** | Cursor、Claude Code、Windsurf、Copilot（编码侧） | （几乎空白：巨头在补，但未跨异构） |
| **Coding 浅/中** | Diffblue、纯测试工具 | **GitLab Duo、Rovo**（单生态宽编排） |
| **Coding 有意克制** | — | **★ 本产品目标：宽编排 × 异构工具 × 中等 Coding（可外接）** |

**含义**：不要往左上角挤；占领右下/右中「编排宽 + 不绑单生态」。

### 4.2 矩阵 B：单生态绑定 × 跨工具异构

|  | 单生态绑定强 | 跨工具异构强 |
|---|---|---|
| **治理成熟** | GitLab Duo、Rovo、Azure | **★ 本产品必须达到的象限** |
| **治理弱** | 各类 IDE Agent | 脚本+ChatGPT+人工（现状，不可持续） |

**含义**：异构 alone 不够，必须把 **人审、草稿邮件、Jenkins 不替代、审计** 做成可演示的治理能力，否则采购侧会退回「用 Rovo/Duo 附赠」。

### 4.3 本产品坐标（对外话术可用）

> **在「跨异构工具链」轴上偏右，在「Coding 深度」轴上居中偏下，在「治理」轴上偏上——三角定位：Orchestrate · Heterogeneous · Governed。**

## 5. 差异化策略与护城河

### 5.1 明确不做什么（Stop List）

| 不做 | 原因 |
|---|---|
| 不做 AI IDE / 不做代码补全主产品 | 红海；Cursor/Copilot/Claude Code 已统治 |
| 不替代 Jenkins，不推销「迁到某某 CI」 | 与 GitLab 战略相反；保护存量采用路径 |
| 不让 AI 在沙箱里跑「正式回归」 | 合规与环境一致性；正式跑测只在 Jenkins |
| 不自动发送邮件 / 不无人值守回写关键系统 | 对冲 Gartner「40% agentic 项目因治理失败被砍」风险 |
| V1 不做通用 Workflow Builder 大而全 | 先用三个固定业务页跑通；Builder 是长期资产 |
| 不绑定单一 LLM / 不绑 Claude Agent SDK | 采购要求可替换与退出路径 |
| 不把 Docker 做成「测试云」 | Docker = 分析/脚本 Tool，不是执行平台 |

### 5.2 明确主打什么（Do List）

| 主打 | 可执行抓手 |
|---|---|
| **跨异构编排** | Connector 一等公民：Jira、Confluence、GitHub、Jenkins；优先 MCP 兼容 |
| **Jenkins 正式测试中心** | 上传包 → Trigger Job → Poll → AI 汇总美化 → **人审** → 回写 Jira/Confluence → 进 Release 证据 |
| **Release Assistant** | 读 Jira + PR + Template → CR / Checklist / 合规调用 / **邮件草稿** |
| **Governed by Design** | 动作分级（读/写/发送）、全量审计、草稿策略可视化 |
| **Skills + Memory 资产化** | 个人可用、团队 Skill 需管理员审核；Memory 可导出 Markdown/JSON |
| **固定业务页 > 纯 Chat** | Chat 是编排入口，ROI 度量挂在业务页产出物上 |

### 5.3 护城河分层（由易到难、由快到慢）

| 层级 | 资产 | 形成周期 | 说明 |
|---|---|---|---|
| L1 流程契合 | 企业内部 Release Template、Jenkins Job 约定、人审节点 | 1–3 月 | **最快壁垒**：巨头通用产品难贴合私有流程 |
| L2 Connector 质量 | 鉴权、分页、错误恢复、幂等回写、字段映射 | 3–6 月 | 异构集成的工程深度 |
| L3 Skills / Workflow 库 | 测试汇总 Skill、CR Skill、合规 Skill | 6–12 月 | 越用越懂该企业；可审核发布 |
| L4 Memory / 证据库 | 项目记忆、历史 Release 证据、失败模式 | 12 月+ | 迁移成本与信任沉淀 |
| L5 门户化 | AI Native Developer Portal | 18 月+ | 与 Backstage/Port 长期对话的资本 |

**关键判断**：护城河不在模型，而在 **Connector + Workflow + Memory + Skills**（与 [00](./00-原始项目思路.md) 原则一致）。

### 5.4 对「免费附赠 AI」的反制

| 附赠来源 | 用户可能说的话 | 反制话术（对内立项） |
|---|---|---|
| Rovo | 「Jira 里已经能问了」 | 问得到 ≠ 能触发 Jenkins、汇总正式回归、沉淀发布证据并人审回写 |
| Copilot | 「写代码已经够快了」 | 编码只占 ~16% 时间；瓶颈在跨工具与发布治理（见 [01](./01-市场调研.md)） |
| GitLab Duo | 「我们有全生命周期 AI」 | 前提是工具链已在 GitLab；Jenkins+GitHub+Jira 混搭不在其最佳路径 |

## 6. 威胁与机会

### 6.1 短期（0–12 个月）

| 类型 | 内容 | 应对 |
|---|---|---|
| **威胁** | Rovo / Copilot 已采购，日常 Chat 立项被质疑 | V1 ROI 只绑定测试中心+Release 周期指标，不绑「聊天满意度」 |
| **威胁** | GitLab 用 Duo 推动迁离 Jenkins | 对「短期不可能迁 CI」的企业讲存量编排；收集 Job 接口标准 |
| **威胁** | Shadow AI（个人 ChatGPT）绕过 | SSO 统一入口 + 审计；产出物必须带来源链接（Jira/PR/Jenkins） |
| **威胁** | Agentic 项目失败叙事导致预算冻结 | 演示「人审门」与成本按 Skill/Workflow 计量 |
| **机会** | MCP 成为连接标准，Connector 成本下降 | Connector 层原生兼容 MCP |
| **机会** | QA 被 AI 编码加速反压，汇总/证据 toil 上升 | 测试中心做第一个闭环 Demo |
| **机会** | EU AI Act 等合规压力抬升证据留痕价值 | Release 证据包作为合规叙事 |

### 6.2 中期（12–36 个月）

| 类型 | 内容 | 应对 |
|---|---|---|
| **威胁** | Rovo / Duo 经 MCP 补齐「触发外部 CI」 | 深挖 **企业私有 Workflow + 人审模板 + Memory**；保持 Jenkins 一等公民体验 |
| **威胁** | Port/Cortex/Backstage AI 吃掉「门户」心智 | 成为 Portal 的编排插件/模块，或先垂直后门户 |
| **威胁** | 模型厂商应用层上移，企业只买「一个 Agent」 | 保持 LLM 可替换；卖的是编排资产不是模型 |
| **机会** | IDP「agent-operable」成为标配 | 长期路线对齐 AI Native Developer Portal |
| **机会** | 内部跑通后多租户外溢 | 架构预留 tenant_id；Skills 审核机制可产品化 |
| **机会** | 测试 AI 厂商（Katalon 等）需要「证据与协作回写」 | 做编排层合作而非取代 |

## 7. 结论与对 V1 取舍的启示

### 7.1 空档回扣（必须写进所有对内材料）

市场调研与竞品扫描共同指向同一空档：

> **跨异构工具链（尤其 Jira + Confluence + GitHub + Jenkins）的编排层 + 以 Jenkins 为正式测试执行后端 + 默认人审治理（回写确认、邮件仅草稿）。**

- GitLab Duo：编排宽，但控制面在 GitLab，Jenkins 是迁出对象。  
- Rovo：协作与 Jira 深，但不以 Jenkins 正式测试与发布证据链为中心。  
- Copilot/Cursor/Claude Code：编码深，业务流程编排浅。  
- Katalon/Diffblue：测试生成/优化强，跨工具 Release 编排弱。  

**无人同时占据「异构 + Jenkins 正式跑测 + 人审治理 + 固定业务页」这一组合。**

### 7.2 对 V1 的可执行取舍

| 议题 | 建议 | 理由 |
|---|---|---|
| 日常开发助手 vs 测试中心 vs Release | **测试中心 + Release 做深；日常助手做薄（统一检索+Skills 入口）** | 日常助手与 Rovo/Copilot 重叠最高，易被附赠消解（[01](./01-市场调研.md) §6.2） |
| Workflow Builder | **V1 不做通用 Builder**；三个固定页内嵌固化流程 | 先有可度量闭环，再抽象引擎 |
| Coding Agent | **不自研**；需要时外接 Copilot/Claude Code | 避免红海与模型厂冲突 |
| Jenkins | **V1 必做一等公民**（Trigger/Poll/日志/产物链接） | 差异化命脉 |
| 治理 | **V1 必做**：人审回写、邮件草稿、审计日志、动作分级 | 信任与立项续命 |
| Skills | **V1 必做**个人 Skill + 团队审核发布（可先简版） | 资产化起点；对齐 Hermes 范式 |
| Memory | **V1 做**用户/项目层 + 可导出；自动保存策略可保守 | 可迁移=采购加分 |
| Portal / Backstage | **V1 不做目录型门户** | 长期目标，短期分心 |
| LLM | **Adapter 多模型**，不绑 SDK | 架构即卖点 |

### 7.3 竞争策略一句话

**不与 Coding Agent 比谁改代码更快；不与 GitLab/Atlassian 比谁生态更深；只与「现状：人工在 Jira、GitHub、Jenkins、邮箱之间复制粘贴」比谁把正式测试与发布准备做得更短、更可审计。**

### 7.4 建议的下一动作（分析落地）

1. 用目标企业真实 Jenkins Job 做一次「触发→汇总→人审→回写」端到端 PoC，产出时长对比（人工 vs 助手）。  
2. 深测 Rovo / Duo 对「外部 Jenkins」的真实能力边界（是否只能迁出/浅连接）。  
3. 冻结 V1 Connector 范围：Jira、Confluence、GitHub、Jenkins 四件套做透，其余一律 backlog。
