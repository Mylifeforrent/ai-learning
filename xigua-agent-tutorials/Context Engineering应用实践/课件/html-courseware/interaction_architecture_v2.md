# 交互架构设计 v2（22 页版本）

## 课件信息
- 课程：Agent 上下文管理 -- Context Engineering
- 总页数：22
- 交互分布：绿色 2 页 / 黄色 18 页 / 红色 2 页
- 设计原则：教学目标驱动，每个交互必须回答"去掉它学生会少理解什么"

## 交互级别定义
- 绿色（static）：纯展示，CSS 入场动画
- 黄色（light）：卡片展开、hover、tab 切换、GSAP 引导动画
- 红色（heavy）：探索式交互，状态机驱动，需要 hookFn

## 认知类型分类（Bloom 简化）
- F = 事实记忆（Know WHAT）
- U = 概念理解（Know WHY）
- A = 分析应用（Know HOW）
- E = 评价判断（Know WHEN）

## 第一章：认知升维（5 页）

### S001 封面
- **教学目标**：3 秒内传达课程主题和学员定位
- **认知类型**：无（元信息）
- **交互等级**：绿色
- **展示形式**：标题 + 副标题 + 前置要求，fade-in 入场
- **第一性原理推导**：封面是"导航信号"而非"学习内容"，任何交互都会分散对主题定位的注意力。3 秒法则——学员打开课件后应在 3 秒内知道"这门课讲什么、我需要什么基础"
- **动画**：标题从底部 fade-up（0.6s），副标题延迟 0.3s fade-in，前置要求最后出现
- **交互**：无

### S002 为什么需要上下文工程
- **教学目标**：从"记忆管理"升维到"上下文工程"，建立供需模型（仓库管理员 vs 策展人）
- **认知类型**：U（概念理解）
- **交互等级**：黄色
- **展示形式**：渐进式揭示 + 对比表 + 五维高亮
- **第一性原理推导**：学员已有"记忆管理"的知识锚点（前课学过 mem0），需要从已知出发扩展到新概念。供需模型的核心是"对比"——左边是已知的供给侧，右边是待学的消费侧。五维对比表必须逐行出现，让学员先锚定已知（供给侧列），再看新知（消费侧列），这比同时展示更符合认知加工顺序。
- **去掉交互会少什么**：如果对比表一次性展示，学员视线会随机扫描，无法形成"已知→新知"的认知桥接。
- **动画**：
  1. 先出现"仓库管理员"图标+标签（左侧），停顿 0.5s
  2. 出现 vs 分隔线 + "策展人"图标+标签（右侧）
  3. 对比表逐行滑入（每行间隔 0.3s），供给侧列先出现（0.2s 后消费侧列跟进）
  4. 底部出现"记忆只是上下文的 2/10"的强调文字（红色脉冲）
- **交互**：hover 对比表的每行，高亮整行并放大关键词

### S003 三层递进模型（已调整：嵌套矩形方案）
- **教学目标**：理解 PE / MM / CE 三层的包含关系和边界，明确"本课在第三层"
- **认知类型**：U（概念理解）
- **交互等级**：黄色
- **展示形式**：嵌套矩形（俄罗斯套娃俯视图）逐层构建动画
- **第一性原理推导**：递进关系的本质是"包含"。嵌套矩形（最外层大框 CE，中框 MM，最内层小框 PE）比垂直堆叠更准确传达"包含关系"——堆叠容易误读为"并列层"。逐层从内到外构建，让学员先锚定最熟悉的 PE，再扩展到 MM（前课），最后到 CE（本课）。右侧标注"前课/本课"定位。
- **去掉动画会少什么**：三层同时出现缺乏"包含"和"递进"的感知，变成"三个并列概念"而非"三层嵌套模型"。嵌套的构建过程本身就是教学——先小后大，传达"CE 包含 MM，MM 包含 PE"。
- **动画**：
  1. 最内层 PE 小框出现在中央，附带定义（"写好一句指令"）和时间尺度（"静态"），停留 1s
  2. MM 中框从 PE 四周扩展出现，包裹 PE，附带定义和时间尺度
  3. CE 大框最后扩展出现，包裹 PE+MM，覆盖最大面积
  4. 右侧出现标注箭头："前课在这里（MM）→ 本课在这里（CE）"
- **交互**：hover 每层可展开详细定义和典型工具

### S004 Context Rot
- **教学目标**：打破"窗口越大越好"的错觉，用数据建立"有效窗口 = 宣传的 50-65%"的认知
- **认知类型**：U（概念理解，反直觉）
- **交互等级**：黄色
- **展示形式**：悬念→数据冲击 + 柱状图动画
- **第一性原理推导**：反直觉内容需要"认知冲突"驱动。先制造预期（"1M 窗口够用吗？"），再用 RULER 数据打破预期（"只有 50-65%"）。柱状图用"宣传窗口 vs 有效窗口"双柱对比，差距的视觉冲击比纯数字更强。四个模型并排排列，强化"所有模型都有这个问题"的普遍性。
- **去掉交互会少什么**：直接给结论缺乏认知冲击。学员不会真正"感受到"差距的严重性，容易停留在"知道但不在意"的状态。
- **动画**：
  1. 大字问题："你买了 1M 窗口，能用多少？" 居中显示
  2. 停顿 1.5s（制造悬念）
  3. 问题上移，下方出现四组双柱图（宣传/有效），宣传柱先到满高度
  4. 有效柱从 0 增长到 50-65% 高度，差距部分标红
  5. 底部滑入结论："有效窗口 ≈ 宣传的 50-65%"（红色强调）
  6. 压缩启动点建议以小字标注在各模型下方
- **交互**：hover 每组柱状图弹出该模型的详细数据 tooltip（宣传值、有效值、建议压缩点）

### S005 分层容器模型（已调整：从鱼缸改为分层容器交互图）
- **教学目标**：建立上下文窗口的六模块分层结构心智模型，为第二章的六模块逐一拆解做预览
- **认知类型**：U（概念理解，框架建立）
- **交互等级**：黄色
- **展示形式**：分层容器交互图。矩形容器内从上到下六个水平层，按 token 占比分配层高（对话历史最厚）。每层标注模块名称、性质标签（静态/动态/按需/持久/外部）和 token 占比。推理引擎在容器正中央。右侧用连线标注五大策略映射（预览）。容器上方红色虚线（有效窗口上限）。
- **第一性原理推导**：分层容器比鱼缸隐喻更精准传达"六类信息按比例堆叠"的概念。层高按 token 占比分配，学员一眼就能看出"对话历史占比最大"。右侧策略连线为第三章做预览，建立"模块→策略"的初步关联。
- **去掉动画会少什么**：静态容器图缺乏"逐层构建"的过程感，学员无法直觉感受到"六类信息逐一注入窗口"这个核心概念。
- **动画**：
  1. 矩形容器轮廓出现（空容器），上方红色虚线标注"有效窗口上限"
  2. 六个水平层从底部依次堆叠入场（每层间隔 0.4s），每层按 token 占比分配高度
  3. 每层入场时标注模块名称 + 性质标签 + token 占比百分比
  4. 推理引擎图标在容器正中央出现
  5. 右侧五大策略连线依次出现（预览，淡色），连接到相关层
  6. 最后高亮对话历史+工具上下文层，脉冲提示"合计 > 50%"
- **交互**：悬停层高亮+放大占比数字，点击展开该模块的简要说明卡片

## 第二章：六大功能模块（7 页）

### S006 六模块全景探索器（已调整：复用 S005 分层容器布局 + 逐模块深入探索）
- **教学目标**：建立六模块作为分析"任何 Agent 上下文构成"的坐标系，发现"对话历史+工具上下文 = 50%+"
- **认知类型**：F + U（事实记忆 + 概念理解）
- **交互等级**：红色
- **展示形式**：复用 S005 的分层容器布局，但从"预览"转为"逐模块深入探索"。六层变为可点击状态，点击展开详情卡片（名称/隐喻/核心问题/token 占比/典型工具）。全部点击后，对话历史+工具上下文层自动加粗边框，弹出"合计 > 50%"。
- **第一性原理推导**：与 S005 视觉框架一致，空间记忆连续。学员在 S005 已建立"分层容器=上下文窗口"的心智模型，S006 直接复用该框架深入探索每层。探索式交互让学员发现"重点在哪里"的结论，比直接告诉更有冲击力。坐标系类知识的教学目标不是"记住列表"而是"形成空间化的思维工具"。
- **去掉交互会少什么**：退化为列表阅读，学员会把六模块当成"又一个要背的列表"而非"可以用来分析任何 Agent 的思维坐标系"。
- **动画**：
  1. S005 的分层容器以完整状态入场（继承前页的视觉记忆）
  2. 每层增加可点击提示（微小脉冲光标）
  3. 初始状态：所有层显示模块名称，但详情卡片未展开
- **交互（状态机驱动）**：
  - 点击任意层 → 该层向右展开详情卡片（名称/隐喻/核心问题/token 占比百分比/典型工具）
  - 已展开的层保持高亮边框
  - 当全部 6 层都展开后 → 对话历史+工具上下文层自动加粗边框并弹出标注："这两个模块合计 > 50%"
  - 这个"发现时刻"是教学设计的核心——学员通过自主探索得出"重点在哪里"的结论

### S007 系统提示层
- **教学目标**：理解系统提示的 6 层拼接顺序，以及为什么适合 Prompt Caching
- **认知类型**：F + A（事实记忆 + 分析应用）
- **交互等级**：黄色
- **展示形式**：垂直层叠可视化 + 点击展开
- **第一性原理推导**：系统提示的核心特征是"多层拼接"和"静态不变"。层级结构天然适合垂直堆叠的空间编码。6 层同时展开会信息过载（每层包含文件名+内容概述+token 估算），点击展开是最自然的渐进揭示方式。底部标注"静态 → 适合 Caching"将模块知识与后续策略知识关联。
- **去掉交互会少什么**：6 层内容全部展开时信息量过大（约 18 个信息点），超出单页认知负荷上限。
- **动画**：6 层色块从底部依次堆叠（每层 0.3s）
- **交互**：点击每层展开侧边详情面板（文件名、内容概述、token 估算），同一时间只展开一层（手风琴模式），底部固定显示"总 token 估算"和"Caching 适配提示"

### S008 对话历史管理层
- **教学目标**：理解"保留多少轮 / 何时压缩 / 摘要注入位置"三个核心决策
- **认知类型**：A（分析应用，策略选择）
- **交互等级**：黄色
- **展示形式**：三策略 Tab 切换
- **第一性原理推导**：三个策略是"三选一或组合"的决策问题。学员需要看到每个策略的机制、优点、局限，然后做出判断。Tab 切换是对比式学习的最佳 UI 模式——保持上下文一致（都在同一页同一位置），只切换内容，方便来回对比。
- **去掉交互会少什么**：三个策略如果垂直排列在一页，学员需要上下滚动对比，认知负荷更高。Tab 强制"聚焦一个、对比另一个"的学习节奏。
- **动画**：Tab 切换时内容区 crossfade（0.3s）
- **交互**：三个 Tab（截断/压缩/摘要），每个 Tab 内包含：机制示意（简图）、适用场景、代码片段、优缺点对比

### S009 记忆检索注入层
- **教学目标**：理解 Just-in-time 原则和四类型分组（user/feedback/project/reference）
- **认知类型**：U + A（概念理解 + 分析应用）
- **交互等级**：黄色
- **展示形式**：四类型卡片 + JIT 流程图
- **第一性原理推导**：四类型分组是分类知识，卡片布局是分类展示的最佳形式（视觉分组+平行对比）。JIT 原则是行为准则（"每次推理都执行 search"），需要用流程图强调"每次"而非"有时"。
- **去掉交互会少什么**：四类型细节展开会让页面过长，卡片折叠控制信息密度。
- **动画**：四张卡片从左到右依次入场（stagger 0.2s），上方 JIT 流程条先出现
- **交互**：点击每张卡片展开该类型的示例内容和"何时注入"说明

### S010 工具上下文管理层
- **教学目标**：认识到 100 个工具占 30-40% 窗口的严重性，掌握分级管理策略
- **认知类型**：U + A（概念理解 + 分析应用）
- **交互等级**：黄色
- **展示形式**：分级阈值可视化 + 策略卡片
- **第一性原理推导**：工具管理的核心是"数量决定策略"。学员需要建立"工具数量→对应策略"的映射关系。分级展示（<10 / 10-30 / 30-100 / 100+）比线性叙述更直观，因为分级本身就是管理策略的核心逻辑。
- **去掉交互会少什么**：四个分级的策略细节同时展示信息量过大，按级展示聚焦注意力。
- **动画**：顶部显示工具数量轴（0→100+），四个区间依次高亮
- **交互**：点击/hover 每个区间，下方展示该级别的管理策略详情（全量加载/按分类加载/动态加载/分级+描述压缩）

### S011 任务状态层
- **教学目标**：理解 Scratchpad 模式和 Write 卸载-加载模式为什么能保住跨轮次状态
- **认知类型**：U（概念理解）
- **交互等级**：黄色
- **展示形式**：前后对比 + 代码示意
- **第一性原理推导**：Scratchpad 的价值通过"有 vs 无"的对比最清晰。左侧展示"无 Scratchpad：压缩后断片"，右侧展示"有 Scratchpad：完整回忆"。对比是最强的说服形式——不需要解释"为什么好"，只需要展示"差距有多大"。
- **去掉交互会少什么**：如果只展示"有 Scratchpad"的情况，学员无法感知其价值。对比的存在本身就是教学设计的核心。
- **动画**：左右面板同时从两侧滑入，中间 vs 分隔线
- **交互**：hover 左侧面板高亮"断片处"（红色标记），hover 右侧面板高亮"被 Scratchpad 保住的信息"（绿色标记）

### S012 外部知识层
- **教学目标**：理解 RAG vs 全上下文的成本/延迟/信息量权衡，建立"RAG 为默认、长上下文为补充"的决策框架
- **认知类型**：E（评价判断）
- **交互等级**：黄色
- **展示形式**：双栏对比 + 数据高亮 + 决策树
- **第一性原理推导**：这是一个"选型决策"问题。选型的关键是"在什么维度上比较"。对比表帮助学员看到多维度差距（成本 1250x、延迟 30-60x），决策树帮助学员内化"什么场景用什么方案"。数据冲击（$0.00008 vs $0.10）比语言描述更有说服力。
- **去掉交互会少什么**：hover 高亮帮助学员聚焦关键数据行，避免在密集对比表中迷失。
- **动画**：对比表整体入场，然后成本行和延迟行依次脉冲高亮（引导视线到最关键数据）
- **交互**：hover 行高亮；底部决策树可展开"何时用 RAG / 何时补充长上下文 / 最优组合"三个场景

## 第三章：五策略框架（5 页）

### S013 五策略总览
- **教学目标**：建立 W/S/C/I/C 五策略作为"遇到问题先查清单"的操作手册
- **认知类型**：F + U（事实记忆 + 概念理解）
- **交互等级**：红色
- **展示形式**：五策略探索器（五边形/环形布局 + 点击展开）
- **第一性原理推导**：这是全课第二个"坐标系"（第一个是 S006 六模块）。与 S006 相同的教学逻辑：坐标系需要空间化记忆。五个策略的关键属性是"正交性"（可组合使用），五边形布局视觉上传达"五个独立维度"。探索式交互让学员发现"Claude Code 同时用了全部五个"这个结论，比直接告诉他们更有冲击力。
- **去掉交互会少什么**：退化为五行定义表，学员记住的是"五个名词"而非"五个可组合的决策维度"。
- **动画**：
  1. 五个策略节点在五边形位置依次出现
  2. 节点之间连线（表示可组合），连线入场
  3. 中心显示"决策清单"标签
- **交互（状态机驱动）**：
  - 点击任意策略节点 → 展开详情卡片（机制/典型实现/何时使用/优先级排名）
  - 已展开节点高亮保持，连线加粗
  - 全部展开后 → 自动播放"优先级排序"动画：节点按 Cache→Isolate→Write→Select→Compress 顺序依次放大并编号
  - 底部出现：Claude Code 使用了全部 5 个策略（五个勾号依次出现）

### S014 三种压缩技术对比
- **教学目标**：掌握观察遮蔽 vs LLM 摘要 vs 工具结果清除的适用边界，建立"场景→技术"映射
- **认知类型**：A + E（分析应用 + 评价判断）
- **交互等级**：黄色
- **展示形式**：三列并排对比 + JetBrains 数据高亮
- **第一性原理推导**：三种技术是"场景决定选择"的关系，不是"谁更好"。并排对比是传达"各有适用场景"的最佳布局（避免暗示线性优劣）。JetBrains 数据（成本 -52%、解决率 +2.6%）是"简单方法不一定差"的证据，需要数据高亮制造认知冲击。
- **去掉交互会少什么**：纯文字描述三种技术的差异需要学员自行对比，hover 高亮差异维度减少认知加工成本。
- **动画**：三列卡片从左到右依次入场
- **交互**：hover 任意维度行（如"额外延迟"）时，三列该行同时高亮，方便横向对比；底部 JetBrains 数据区 hover 展开实验细节

### S015 策略-模块交叉矩阵
- **教学目标**：看到五策略和六模块的组合关系，发现"热区集中在压缩+对话历史、缓存+系统提示"
- **认知类型**：A（分析应用）
- **交互等级**：黄色
- **展示形式**：5x6 热力图矩阵 + hover 十字线
- **第一性原理推导**：交叉矩阵是二维关系的天然表达。热力图用颜色深浅编码"应用频率/重要性"，比纯文字矩阵信息密度更高。hover 十字线帮助学员在 30 个格子中聚焦当前行列交叉点，解决"密集矩阵难以阅读"的问题。
- **去掉交互会少什么**：5x6=30 个格子的纯静态矩阵视觉噪声太大，hover 十字线是降低认知负荷的必要工具。
- **动画**：矩阵格子从左上到右下依次填充颜色（瀑布效果）
- **交互**：hover 任意格子高亮整行+整列（十字线），tooltip 显示该策略在该模块的具体应用方式

### S016 决策优先级
- **教学目标**：内化"Cache 首日启用"的优先级，建立五级递进决策路径
- **认知类型**：A + E（分析应用 + 评价判断）
- **交互等级**：黄色
- **展示形式**：五级递进阶梯 + 每级详情展开
- **第一性原理推导**：优先级是"先做什么、后做什么"的时序问题。阶梯/楼梯的空间隐喻（从高到低或从左到右）直觉传达"先后顺序"。关键教学点是"Cache 是零成本优化，应第一个做"——这需要在视觉上给 Cache 最高位置/最大面积。
- **去掉交互会少什么**：五级策略的详细说明同时展示会过载，递进展开控制节奏。
- **动画**：五级阶梯从第一级（Cache）开始依次构建，每级带标签
- **交互**：点击每级展开详情面板：该策略的适用前提、实施成本、预期收益、典型案例

### S017 四种失败模式
- **教学目标**：识别 Poisoning/Distraction/Confusion/Clash 四种反模式，建立诊断能力
- **认知类型**：A（分析应用，诊断）
- **交互等级**：黄色
- **展示形式**：四卡片 + 案例展开
- **第一性原理推导**：失败模式是"反面教材"——学员通过识别"什么是错的"来强化"什么是对的"。每种失败模式需要"症状描述 + 真实案例 + 修复建议"三部分。四种模式信息量较大，卡片折叠控制密度。
- **去掉交互会少什么**：四种失败模式的详细案例全部展开会让页面变成"长文阅读"，卡片折叠让学员按需深入。
- **动画**：四张卡片带警告图标依次入场（stagger 0.25s），卡片带红色左边框暗示"危险"
- **交互**：点击每张卡片展开：症状描述、触发条件、真实案例（mini-OpenClaw 或 Claude Code 场景）、修复建议

## 第四章：决策内化（5 页）

### S018 mini-OpenClaw 六模块标注
- **教学目标**：将六模块坐标系应用到真实代码，建立"文件→模块"的映射能力
- **认知类型**：A（分析应用，框架→实战映射）
- **交互等级**：黄色
- **展示形式**：双栏映射（左侧文件列表 + 右侧六模块雷达图/标注）
- **第一性原理推导**：这是"概念→实战"的桥接页。学员已经知道六模块的定义（第二章），现在需要练习"看到真实代码时能识别出哪个模块"。双栏布局（代码↔概念）是建立双向联系的最佳形式。左侧 7 个文件点击后右侧高亮对应模块，帮助学员练习分类。
- **去掉交互会少什么**：静态标注表是"给答案"，点击映射是"做练习"。主动加工（点击查看）比被动阅读（直接看表）形成更深的记忆编码。
- **动画**：左侧文件列表入场，右侧六模块雷达图入场
- **交互**：点击左侧任意文件 → 右侧对应模块扇区高亮 + 弹出该文件在该模块中的角色说明；可依次点击所有 7 个文件完成"全景标注"

### S019 mini-OpenClaw 五策略体检
- **教学目标**：用五策略框架诊断 mini-OpenClaw 的上下文管理现状（红绿灯体检表）
- **认知类型**：A + E（分析应用 + 评价判断）
- **交互等级**：黄色
- **展示形式**：红绿灯体检表 + 诊断详情展开
- **第一性原理推导**：体检表是"框架应用"的练习。红绿灯（绿=已实现/黄=部分实现/红=未实现）用颜色编码状态，直觉可读。学员需要看到"哪些策略已用、哪些未用"的全貌，再深入每个策略的诊断详情。这是从"理解框架"到"应用框架"的认知跃迁。
- **去掉交互会少什么**：体检表展开后信息量大（5 策略 x 诊断详情），折叠控制密度。
- **动画**：五行体检表入场，每行左侧灯泡依次亮起（绿/黄/红）
- **交互**：点击每行展开诊断详情：当前实现状态、缺失原因、改进建议、预期 token 节省

### S020 场景-策略匹配矩阵
- **教学目标**：建立"七类常见场景→最佳策略组合"的选型直觉
- **认知类型**：E（评价判断）
- **交互等级**：黄色
- **展示形式**：场景卡片 + 策略推荐
- **第一性原理推导**：场景选型是最高层次的认知目标——"遇到新场景知道用什么策略"。七类场景（SE Agent/客服/调研/教学...）代表学员未来会遇到的真实情况。每个场景配一套策略组合推荐，帮助学员从"理解单个策略"升级到"组合运用策略"。
- **去掉交互会少什么**：七类场景的策略组合同时展示信息量过大，按场景切换聚焦注意力。
- **动画**：七张场景卡片网格排列入场
- **交互**：点击场景卡片 → 展开该场景的策略推荐组合（五个策略各标注"必用/推荐/不适用"），底部显示推荐理由

### S021 Token 经济学 + 优化路线
- **教学目标**：理解成本瀑布（从未优化到全优化的成本下降路径）和六阶段递进优化
- **认知类型**：A（分析应用）
- **交互等级**：黄色
- **展示形式**：成本瀑布图 + 六阶段进度条
- **第一性原理推导**：成本优化的核心认知是"叠加效应"——每个策略单独节省 20-30%，组合后可能节省 80%+。瀑布图是展示"逐步下降"的最佳图表类型（每个柱子从前一个终点开始，向下到新终点）。六阶段递进条给出"从哪里开始优化"的操作路线。
- **去掉交互会少什么**：瀑布图的每个"台阶"需要标注具体策略和节省比例，hover 展开避免标注过密。
- **动画**：瀑布图从左到右逐级构建，每级标注策略名称和节省百分比
- **交互**：hover 每个瀑布级 → tooltip 显示该策略的实施方式和成本数据；底部六阶段进度条可点击查看每阶段的详细操作清单

### S022 知识图谱总结
- **教学目标**：回顾全课框架，建立概念间连接，提供能力自检清单
- **认知类型**：综合回顾
- **交互等级**：绿色
- **展示形式**：知识图谱全景 + 自检清单
- **第一性原理推导**：课程结尾需要"收束"而非"展开"。知识图谱帮助学员在脑中建立概念间的连接网络。自检清单提供"学完能做什么"的锚点。此页信息是全课的压缩总结，不需要新的交互——学员的注意力应该从"学习新知识"转向"回顾和整合"。
- **去掉交互的理由**：总结页的目的是"整体鸟瞰"，交互会让学员陷入局部细节而非全局整合。CSS 动画引导视线从图谱到自检清单即可。
- **动画**：知识图谱节点依次出现并连线（模拟"概念网络构建"），自检清单逐条 fade-in
- **交互**：无（纯展示，CSS 动画引导）

## 交互设计一致性规则

为减少学员的"学习交互界面"的认知成本，以下交互模式在全课件中保持一致：

### 1. 对比类内容 → 统一用 hover 行高亮
- 适用页面：S002, S004, S012, S014, S015
- 行为：hover 任意行 → 该行背景色加深 + 关键数据放大

### 2. 分类/模块类内容 → 统一用点击展开卡片
- 适用页面：S007, S009, S010, S017, S018, S019, S020
- 行为：点击卡片 → 下方滑出详情面板，再次点击收起
- 约束：同类卡片手风琴模式（展开新卡片自动收起旧卡片）

### 3. 多策略/多方案选择 → 统一用 Tab 切换
- 适用页面：S008
- 行为：点击 Tab → 内容区 crossfade 切换

### 4. 嵌套/递进类内容 → 统一用逐层构建动画
- 适用页面：S003, S016
- 行为：层级从基础到高级依次构建

### 5. 坐标系类内容 → 统一用探索式交互（红色）
- 适用页面：S006, S013
- 行为：点击节点展开 → 全部展开后触发总结动画

### 6. 分层容器类内容 → 统一用分层堆叠 + 悬停高亮
- 适用页面：S005, S006
- 行为：悬停层高亮+放大占比，S006 增加点击深入探索

### 7. 前后对比类内容 → 统一用左右分屏
- 适用页面：S011
- 行为：左右面板，hover 高亮差异点
