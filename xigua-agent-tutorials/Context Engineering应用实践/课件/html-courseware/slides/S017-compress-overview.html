Compress：上下文压缩
信息不丢失（或可控损失），但占用的 Token 大幅减少
📜
Agent 每轮工具调用产生大量中间产物，上下文窗口快速膨胀。 Compress 的核心：用更少的 Token 表达相同（或关键）信息。四种技术，成本递增，可叠加使用。
零成本 成本递增 ────────────> 重启代价
1
工具结果清除
零成本
工具调用完成后，丢弃原始返回，仅保留一行结论摘要。Agent 已提取信息，原始数据不再需要。
-81% Token 消耗
2
观察遮蔽
配置成本
保留 Thought + Action 推理链，将旧轮次 Observation 替换为占位符。当前轮完整保留。
-52% 成本 · +2.6% 解决率
3
对话动态压缩
计算成本
接近上限时，LLM 将历史对话压缩为摘要。渐进式有损压缩，保持无限会话长度。
~70% 窗口释放 · 有损
4
Compaction 压缩重启
重启代价
上下文触顶时，整个对话压缩为摘要后重启。"存档 + 新游戏+"——丢弃原始对话，只带走关键结论。
-93% 窗口释放 · 180K→12K
四种技术可叠加使用：先清除工具结果（即时），再遮蔽旧观察（配置一次）， 渐进摘要保持会话，最终触顶时 Compaction 重启。接下来逐一深入。
