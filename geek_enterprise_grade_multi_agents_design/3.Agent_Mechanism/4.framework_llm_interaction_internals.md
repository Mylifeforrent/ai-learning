# Agent 框架底层与 LLM 交互机制揭秘 —— 从 HTTP 到 SDK 到框架封装

> **本文是 `tool_calling_message_flow.md` 的进阶篇**。上文讲解的是 Tool Calling 的消息流转逻辑，本文将向下深挖一层：框架底层到底是怎么跟大模型 API "说话"的？那些方便的对象（如 `assistant_message.tool_calls`）是怎么从 HTTP 响应中被解析出来的？

---

## 1. 全景架构：三层抽象

所有框架，无论 Python (LangChain, CrewAI) 还是 Java (LangChain4j, Spring AI)，都遵循**同一个三层架构**：

```
┌─────────────────────────────────────────────────────────────────┐
│                      你写的业务代码                               │
│   result = agent.invoke("查天气")                               │
│   message.tool_calls[0].function.name                          │
└────────────────────────────┬────────────────────────────────────┘
                             │ 调用
┌────────────────────────────▼────────────────────────────────────┐
│                  框架 SDK 封装层                                  │
│   LangChain / CrewAI / LangChain4j / Spring AI                  │
│   负责：                                                         │
│   ① 把 Python/@tool 函数签名 → 转成 JSON Schema                 │
│   ② 组装 messages + tools 列表                                   │
│   ③ 发 HTTP 请求                                                │
│   ④ 解析 HTTP 响应 JSON → 封装成语言级对象 (AIMessage/ToolCall)  │
│   ⑤ 路由判断 (有 tool_calls? → 执行工具; 没有? → 返回最终回答)   │
└────────────────────────────┬────────────────────────────────────┘
                             │ HTTP POST (JSON)
┌────────────────────────────▼────────────────────────────────────┐
│                    LLM API 服务端                                 │
│   OpenAI / Claude / 阿里通义 / 本地 Ollama                      │
│   接收 JSON → 模型推理 → 返回 JSON                               │
└─────────────────────────────────────────────────────────────────┘
```

> 🔑 **核心认知**：你在代码里写的 `message.tool_calls` 并不是什么魔法。框架帮你做的事情就是：发 HTTP 请求 → 拿到原始 JSON 字符串 → 用 `json.loads()` 解析 → 映射到类/对象的属性上。本质就是一次 API 间的 JSON 序列化/反序列化。

## 2. 从最底层开始：裸 HTTP 请求与响应

### 2.1 发出去的 HTTP 请求长什么样？

不管你用什么框架，最终发给 OpenAI 的都是这样一个 **HTTP POST** 请求：

```http
POST https://api.openai.com/v1/chat/completions
Content-Type: application/json
Authorization: Bearer sk-xxxxx

{
  "model": "gpt-4o",
  "messages": [
    {"role": "system", "content": "你是天气助手"},
    {"role": "user", "content": "北京天气如何？"}
  ],
  "tools": [
    {
      "type": "function",
      "function": {
        "name": "get_weather",
        "description": "查询天气",
        "parameters": {
          "type": "object",
          "properties": {
            "city": {"type": "string", "description": "城市名"}
          },
          "required": ["city"]
        }
      }
    }
  ]
}
```

### 2.2 收到的 HTTP 响应长什么样？

OpenAI 服务端返回的是**纯 JSON 字符串**（一坨文本流通过网络传回来）：

```http
HTTP/1.1 200 OK
Content-Type: application/json

{
  "id": "chatcmpl-9abc123",
  "object": "chat.completion",
  "model": "gpt-4o-2024-08-06",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": null,
        "tool_calls": [
          {
            "id": "call_abc123",
            "type": "function",
            "function": {
              "name": "get_weather",
              "arguments": "{\"city\": \"Beijing\"}"
            }
          }
        ]
      },
      "finish_reason": "tool_calls"
    }
  ],
  "usage": {
    "prompt_tokens": 82,
    "completion_tokens": 17,
    "total_tokens": 99
  }
}
```

> 📌 **请注意**：`tool_calls[0].function.arguments` 的值是一个**字符串** `"{\"city\": \"Beijing\"}"`，不是 JSON 对象！这就是为什么框架里还需要对它再做一次 `json.loads()` 来把 arguments 从字符串转为字典/Map。

## 3. Python 框架如何把 HTTP 响应变成你用的对象

### 3.1 OpenAI 官方 Python SDK 的封装

OpenAI 的 SDK 底层做了以下步骤（伪代码）：

```python
# ━━━━ 你写的代码 ━━━━
response = client.chat.completions.create(model="gpt-4o", messages=[...], tools=[...])
message = response.choices[0].message
print(message.tool_calls[0].function.name)  # → "get_weather"

# ━━━━ SDK 底层帮你做的事情（简化版源码逻辑）━━━━

# 第一步：发送 HTTP 请求
import httpx
raw_response = httpx.post(
    "https://api.openai.com/v1/chat/completions",
    headers={"Authorization": f"Bearer {api_key}"},
    json={"model": "gpt-4o", "messages": [...], "tools": [...]}
)

# 第二步：拿到的是一串纯 JSON 文本
raw_json_str = raw_response.text
# 内容: '{"id":"chatcmpl-xxx","choices":[{"message":{"role":"assistant","content":null,"tool_calls":[...]}}]}'

# 第三步：json.loads 解析为 Python 字典
import json
data = json.loads(raw_json_str)
# data = {"id": "chatcmpl-xxx", "choices": [{"message": {"role": "assistant", ...}}]}

# 第四步：用 Pydantic 模型映射字典到类实例（关键一步！）
# OpenAI SDK 内部定义了这些类：
class Function(BaseModel):
    name: str
    arguments: str  # ⚠️ 注意：这里还是字符串！

class ToolCall(BaseModel):
    id: str
    type: str
    function: Function

class Message(BaseModel):
    role: str
    content: Optional[str]
    tool_calls: Optional[List[ToolCall]]

class Choice(BaseModel):
    index: int
    message: Message
    finish_reason: str

class ChatCompletion(BaseModel):
    id: str
    choices: List[Choice]

# SDK 用 Pydantic 自动将字典映射为类实例
response = ChatCompletion(**data)

# 第五步：你就可以用 . 号访问属性了
response.choices[0].message.tool_calls[0].function.name  # → "get_weather"
response.choices[0].message.tool_calls[0].function.arguments  # → '{"city":"Beijing"}'（字符串！）

# 所以框架执行工具时还需要再解析一次：
args = json.loads(response.choices[0].message.tool_calls[0].function.arguments)
# args = {"city": "Beijing"}（现在才是 Python 字典）
```

### 3.2 LangChain 在 OpenAI SDK 之上又包了一层

LangChain 在 OpenAI SDK 的基础上又做了进一步封装：

```python
# ━━━━ 你写的 LangChain 代码 ━━━━
from langchain_openai import ChatOpenAI
from langchain_core.tools import tool

@tool
def get_weather(city: str) -> str:
    """查询天气"""
    return "晴天25度"

llm = ChatOpenAI(model="gpt-4o")
llm_with_tools = llm.bind_tools([get_weather])
ai_message = llm_with_tools.invoke("北京天气？")

# 你直接可以用：
ai_message.tool_calls
# → [{'name': 'get_weather', 'args': {'city': 'Beijing'}, 'id': 'call_abc123'}]
# 注意：args 已经是字典了！LangChain 帮你多做了一步 json.loads()

# ━━━━ LangChain 底层做的事情（简化伪代码）━━━━

# 1. bind_tools() 做了什么？
#    读取 @tool 装饰器标注的 Python 函数签名 → 自动生成 JSON Schema
def bind_tools(self, tools):
    tool_schemas = []
    for t in tools:
        schema = {
            "type": "function",
            "function": {
                "name": t.name,                           # 从函数名提取
                "description": t.description,             # 从 docstring 提取
                "parameters": t.args_schema.schema()      # 从类型注解生成 JSON Schema
            }
        }
        tool_schemas.append(schema)
    self.bound_tools = tool_schemas      # 存起来，每次请求时自动带上
    return self

# 2. invoke() 做了什么？
def invoke(self, input):
    # 2a. 调用 OpenAI SDK（SDK 再发 HTTP 请求）
    openai_response = self.client.chat.completions.create(
        model=self.model,
        messages=self._convert_to_openai_messages(input),
        tools=self.bound_tools                              # 自动带上工具定义
    )
    
    # 2b. 拿到 OpenAI SDK 已经解析好的对象
    openai_message = openai_response.choices[0].message
    
    # 2c. 再包一层：转成 LangChain 自己的 AIMessage
    #     并且把 arguments 从字符串自动解析成字典！
    tool_calls = []
    if openai_message.tool_calls:
        for tc in openai_message.tool_calls:
            tool_calls.append({
                "name": tc.function.name,
                "args": json.loads(tc.function.arguments),  # ⭐ 自动帮你 json.loads 了！
                "id": tc.id
            })
    
    return AIMessage(
        content=openai_message.content or "",
        tool_calls=tool_calls
    )
```

### 3.3 封装层级全景图

```
你写的代码：ai_message.tool_calls[0]["args"]["city"]
                │
                ▼
LangChain 层：把 OpenAI 的 ToolCall 对象再封装一次
              自动执行了 json.loads(arguments)
              返回 AIMessage(tool_calls=[{"name":..., "args": {字典}, "id":...}])
                │
                ▼
OpenAI SDK 层：把 HTTP JSON 字符串用 Pydantic 映射为类实例
              返回 ChatCompletion(choices=[Choice(message=Message(tool_calls=[ToolCall(...)]))])
                │
                ▼
HTTP 层：     收到原始 JSON 文本
              '{"choices":[{"message":{"tool_calls":[{"function":{"arguments":"{...}"}}]}}]}'
                │
                ▼
OpenAI 服务器：大模型推理 → 生成 JSON 响应
```

## 4. Java 生态完全是同样的原理！

### 4.1 核心结论

> **是的，Java 生态的 LangChain4j、Spring AI、Spring AI Alibaba 的底层原理和 Python 完全一致。** 
> 不同的只是编程语言的语法和类库命名，核心架构（HTTP JSON 交互 → 反序列化 → 对象封装 → Agent 循环）一模一样。

### 4.2 LangChain4j 代码示例与对比

```java
// ━━━━ Java (LangChain4j) ━━━━

// 1. 定义工具（等同于 Python 的 @tool 装饰器）
public class WeatherTools {
    @Tool("查询指定城市的天气")                        // ← 等同于 Python @tool
    public String getWeather(@P("城市名") String city) {
        return city + "今天晴天，25度";
    }
}

// 2. 创建 Agent
ChatLanguageModel model = OpenAiChatModel.builder()
    .apiKey("sk-xxx")
    .modelName("gpt-4o")
    .build();

// 3. 自动绑定工具并运行
Assistant assistant = AiServices.builder(Assistant.class)
    .chatLanguageModel(model)
    .tools(new WeatherTools())                          // ← 等同于 bind_tools()
    .build();

String answer = assistant.chat("北京天气如何？");
System.out.println(answer);
```

**LangChain4j 底层做了什么（与 Python 完全对应）：**

```java
// 伪代码，展示底层原理

// 第一步：通过反射读取 @Tool 注解和方法签名 → 生成 JSON Schema
//     等同于 Python 中 bind_tools() 读取类型注解和 docstring
ToolSpecification spec = ToolSpecification.builder()
    .name("getWeather")
    .description("查询指定城市的天气")
    .addParameter("city", JsonSchemaProperty.STRING, "城市名")
    .build();

// 第二步：发送 HTTP 请求（与 Python 完全相同的 JSON 格式！）
//     Java 用 OkHttp/HttpClient，Python 用 httpx
//     发的和收的 JSON 内容完全一样
HttpResponse response = httpClient.send(
    HttpRequest.newBuilder()
        .uri(URI.create("https://api.openai.com/v1/chat/completions"))
        .header("Authorization", "Bearer sk-xxx")
        .POST(BodyPublishers.ofString(requestJson))   // 同样的 JSON 格式
        .build(),
    BodyHandlers.ofString()
);

// 第三步：JSON 反序列化（等同于 Python 的 json.loads + Pydantic）
//     Java 用 Jackson/Gson，Python 用 Pydantic
ObjectMapper mapper = new ObjectMapper();
ChatCompletionResponse parsed = mapper.readValue(response.body(), ChatCompletionResponse.class);

// 第四步：提取 tool_calls（逻辑完全一致）
List<ToolCall> toolCalls = parsed.getChoices().get(0).getMessage().getToolCalls();
String functionName = toolCalls.get(0).getFunction().getName();         // "getWeather"
String argumentsStr = toolCalls.get(0).getFunction().getArguments();   // "{\"city\":\"Beijing\"}"
Map<String, Object> args = mapper.readValue(argumentsStr, Map.class);  // json.loads 等价操作
```

### 4.3 Spring AI 代码示例

```java
// ━━━━ Java (Spring AI) ━━━━

@Configuration
public class AiConfig {
    
    // 1. 定义工具（Spring AI 用 @Bean + Function 的方式）
    @Bean
    @Description("查询指定城市的天气")                  // ← 等同于 Python docstring
    public Function<WeatherRequest, String> getWeather() {
        return request -> request.city() + "今天晴天，25度";
    }
}

// 2. 在 Controller 中使用
@RestController
public class ChatController {

    private final ChatModel chatModel;

    @GetMapping("/ask")
    public String ask(@RequestParam String question) {
        // Spring AI 底层自动：
        // ① 扫描所有 @Bean Function → 生成 JSON Schema
        // ② 发送 HTTP 请求 (带 tools 参数)
        // ③ 解析响应中的 tool_calls
        // ④ 自动执行对应的 Function Bean
        // ⑤ 将结果以 tool 角色回传 → 发起第二轮请求
        // ⑥ 返回最终自然语言回答
        ChatResponse response = chatModel.call(
            new Prompt(question, 
                OpenAiChatOptions.builder()
                    .function("getWeather")            // 指定可用工具
                    .build())
        );
        return response.getResult().getOutput().getContent();
    }
}
```

## 5. 各框架底层交互对照总表

下表展示各个框架在底层与 LLM 交互的每一步操作中，具体用了什么技术：

| 步骤 | 做什么 | Python (LangChain) | Python (OpenAI SDK) | Java (LangChain4j) | Java (Spring AI) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| ① 工具定义 → Schema | 从代码签名生成 JSON Schema | `@tool` 装饰器 + 类型注解 | 手动写 `tools` 字典 | `@Tool` 注解 + 反射 | `@Bean Function` + `@Description` |
| ② 发送 HTTP 请求 | 将 messages + tools 序列化为 JSON 发送 | httpx (由 OpenAI SDK 调用) | httpx | OkHttp / HttpClient | WebClient / RestTemplate |
| ③ JSON 反序列化 | 将响应 JSON 字符串变为语言级对象 | Pydantic BaseModel | Pydantic BaseModel | Jackson ObjectMapper | Jackson ObjectMapper |
| ④ 提取 tool_calls | 从对象中读取工具调用信息 | `ai_message.tool_calls` | `message.tool_calls` | `message.getToolCalls()` | `response.getToolCalls()` |
| ⑤ 解析 arguments | 将 arguments 字符串解析为字典/Map | `json.loads()` (LangChain 自动做) | `json.loads()` (需手动) | `ObjectMapper.readValue()` | 自动调用 Jackson |
| ⑥ 执行工具 | 调用本地函数获得真实结果 | `ToolNode` 自动执行 | 手动写 if/elif | 反射调用 `@Tool` 方法 | Spring 容器调用 Bean |
| ⑦ 回传结果 | 以 `tool` 角色追加到 messages | `ToolMessage` | 手动构建 dict | `ToolExecutionResultMessage` | 自动追加 |

## 7. 为什么所有框架（不论语言）能共享同一套原理？

根本原因只有一个：

> **所有这些框架与大模型之间的通信，本质上就是在发、收标准的 HTTP JSON 请求。**

- OpenAI 定义了 `/v1/chat/completions` 这个 HTTP API 的 JSON 格式规范。
- 这个规范已经成为了事实上的行业标准（类似于 REST API 对 Web 开发的意义）。
- 所有其他模型提供商（Anthropic、Google、阿里通义、DeepSeek）都实现了**兼容 OpenAI 格式**的 API 接口。
- 因此不管你用 Python 还是 Java，用 LangChain 还是 Spring AI，底层发的 JSON 长一个样，收的 JSON 也长一个样。

框架的区别仅在于：
- **Python 生态**：用 Pydantic 做对象映射，装饰器（`@tool`）做元编程。
- **Java 生态**：用 Jackson 做对象映射，注解（`@Tool`）+ 反射做元编程。
- **Spring 生态额外优势**：借助 Spring 的 IoC 容器和 Bean 管理，工具的注册和执行可以通过依赖注入自动完成。

但打开网络抓包工具一看，发出去和收回来的那坨 JSON 是完全一样的。**语言不同，协议相同。**
